# Morning brief feed

Sideline publishes a small data file every morning for your Claude morning brief.

| | URL |
|---|---|
| JSON (for the brief) | `https://<your-github-user>.github.io/<repo>/data/brief.json` |
| Markdown (human-readable) | `https://<your-github-user>.github.io/<repo>/data/brief.md` |

It is generated by `.github/workflows/brief.yml` (script: `scripts/build-brief.mjs`) and is ready
by **6:45 am Pacific** every day: normally around 4:50–5:50 am PT, with a backup run an hour later.
All times inside are **America/Los_Angeles**.

## Schema (`schema_version: 1`)

```jsonc
{
  "schema_version": 1,
  "generated_at": "2026-11-27T12:52:10.123Z",   // ISO 8601, UTC
  "generated_at_pt": "2026-11-27 4:52 AM PT",
  "timezone": "America/Los_Angeles",
  "date": "2026-11-27",           // the Pacific day the brief covers
  "replay_date": "2026-11-26",    // the day "worth_a_replay" looks at
  "scheduled": true,              // false when run by hand
  "engine_version": 3,            // rating engine version
  "app_url": "https://<user>.github.io/<repo>/",

  "top_games": [ Game ],          // best ~5 games today, by predicted rating (live games use their live rating)
  "favorites_today": [ Game ],    // every game your favorites play today, even low-rated ones, by start time
  "worth_a_replay": [ Game ],     // yesterday's finished games: all Great (85+) up to 8, else the top 5

  "counts": { "games_today": 61, "finished_yesterday": 45, "rated_yesterday": 45 },
  "errors": []                    // data problems (an ESPN endpoint down, etc.); the brief still publishes
}
```

### `Game`

| Field | Example | Notes |
|---|---|---|
| `id` | `"nba:401810123"` | `<league>:<ESPN event id>` |
| `league` | `"NBA"` | short label; `league_key` is the internal key (`nba`, `epl`, `f1`, …) |
| `matchup` | `"Celtics at Lakers"` | soccer: `"Liverpool vs Everton"` (home first); F1: `"Qatar Grand Prix · Race"` |
| `home`, `away` | `"Los Angeles Lakers"` | `null` for F1 |
| `start_time_pt` | `"7:30 PM"` | Pacific; `start_iso` is the exact UTC time |
| `status` | `"scheduled"` | `scheduled`, `live`, `final` or `canceled`; `status_detail` has ESPN's text ("Q3 4:12", "FT") |
| `rating` | `88` | 0–100, or `null` when not rateable |
| `rating_state` | `"predicted"` | `predicted` (before the game), `live` or `final` |
| `band` | `"Great"` | `Dull` 0–39, `OK` 40–64, `Good` 65–84, `Great` 85–100 |
| `reason` | `"Rivalry · Projected within 2.5 points"` | one line, from the components that drove the rating |
| `favorite` | `true` | involves one of your favorite teams |
| `watch` | `["ESPN (YouTube TV)"]` | only broadcasters reachable on your services (config/services.js) |
| `watch_summary` | `"ESPN (YouTube TV)"` | first option, or `"Not on your services"` / `"No TV listing"` |
| `final_score` | `"Lakers 112, Celtics 110 (OT)"` | finished games only |
| `url` | `"https://…/#/game/nba/401810123"` | deep link into the app |

Fields may be added in future versions; existing fields keep their meaning while
`schema_version` stays 1.

## Pointing your morning brief at it

Tell your brief something like: *"Fetch `https://<user>.github.io/<repo>/data/brief.json`. Mention the
top games with their rating, start time and where to watch, every favorites game, and anything
in `worth_a_replay`. If `date` isn't today in Pacific time, say the sports feed is stale."*

## Also published

`/data/ratings/<YYYY-MM-DD>.json`: final ratings for every game of that day (last 14 days). The app
uses these as a head start, so it doesn't refetch every finished game.
